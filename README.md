# Bank Statement Extractor

Turns a bank statement PDF — digital or scanned — into validated, reconciled
structured data. JSON and CSV out, in one command.

> Personal demo project. All sample documents are synthetic and generated by
> `make_sample.py`. No real account data is used anywhere in this repo.

## The problem

Bookkeeping and finance teams retype statements by hand. A 40-line statement
takes 15–20 minutes and the error rate is exactly as bad as you would expect.
The usual "just use an LLM" answer produces JSON that looks right and is
quietly wrong — a dropped row, a debit with the wrong sign, a hallucinated
balance. Nobody notices until the books do not close.

## The approach

Three things, in this order:

1. **Route by document type.** Digital PDFs go through the text layer
   (`pdfplumber`) — cheap and lossless. Only scans get rendered to images and
   sent as vision input, capped at 8 pages.
2. **Constrain the output.** The model returns JSON against a fixed shape,
   validated by a Pydantic schema. Bad dates, unknown categories and missing
   required fields are rejected, not coerced.
3. **Check the arithmetic.** `opening + credits + debits` must equal the
   reported `closing`, within one cent. This is the part that makes the output
   trustworthy: a hallucinated or dropped transaction breaks the sum, and the
   run fails loudly with a non-zero exit code instead of shipping bad data
   downstream.

Step 3 is the whole point. Extraction you cannot verify is not automation,
it is a new source of errors.

## Run it

```bash
pip install -r requirements.txt
export ANTHROPIC_API_KEY=sk-...

python make_sample.py                    # generate a test statement
python extract.py sample_statement.pdf --out output/
```

Output:

```
  source        : sample_statement.pdf  [text layer]
  transactions  : 34
  money in      : 18937.42
  money out     : -518.16
  reconciliation: PASS (expected 30899.81, reported 30899.81)
  tokens        : 1842 in / 3106 out
  written       : output/sample_statement.json, output/sample_statement.csv
```

Exit code is `1` when reconciliation fails, so it drops straight into a cron
job or CI step without extra glue.

## Offline tests

```bash
python test_pipeline.py
```

Runs without an API key. Covers PDF parsing, schema rejection of malformed
model output, and both reconciliation branches — the passing case and a
deliberately corrupted closing balance that must be flagged.

## Output shape

```json
{
  "bank_name": "NORTHWIND COMMERCIAL BANK",
  "account_holder": "Meridian Logistics LLC",
  "account_number_masked": "****-****-4471",
  "currency": "USD",
  "period_start": "2026-05-01",
  "period_end": "2026-05-31",
  "opening_balance": "12480.55",
  "closing_balance": "30899.81",
  "transactions": [
    {
      "date": "2026-05-02",
      "description": "STRIPE PAYOUT",
      "amount": "3184.20",
      "balance": "15664.75",
      "category": "Income"
    }
  ]
}
```

Amounts are signed — negative out, positive in — so the data sums correctly
without a separate debit/credit column to interpret.

## Layout

```
schema.py           Pydantic models + reconciliation logic
extract.py          PDF routing, model call, CLI
make_sample.py      Synthetic statement generator
test_pipeline.py    Offline tests, no API key required
```

## Extending it

The schema is the contract. Point it at invoices or purchase orders by
changing `Statement` and the shape block in the system prompt; the routing,
validation and reconciliation layers stay as they are.
